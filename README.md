# דאשבורד לניהול לידים חכם

פרויקט הדגמה לימודי: דאשבורד סטטי בעברית לניהול לידים בעסק קטן. **כל השמות, פרטי הקשר והנתונים פיקטיביים.**

> **סטטוס:** כל 10 היכולות של `SPEC.md` בנויות ונבדקות אוטומטית.
> הנתונים נשמרים רק בדפדפן שבו עובדים.
>
> **פרסום:** האתר מוכן לפרסום ב-GitHub Pages בכתובת המתוכננת `https://taliasnir-prog.github.io/lead-dashboard/`. **הוא עוד לא פורסם ולא נבדק בכתובת הזו.**

## מה יש בדאשבורד

- 4 כרטיסי סיכום ותרשים לפי מקור הגעה, תמיד על כלל הלידים.
- טבלת לידים ממוינת לפי דירוג עדיפות שקוף, עם סימון "באיחור".
- חיפוש לפי שם וסינון לפי סטטוס, מקור ונציג.
- פרטי ליד, עריכה והוספה בחלון, עם בדיקות תקינות.
- שמירה ב-localStorage ואיפוס לנתוני הדמה, עם אישור.
- עברית ו-RTL, התאמה למחשב ולסלולרי, וניווט מלא במקלדת.

## הרצה מקומית

הקוד נטען כ-ES modules, ולכן צריך שרת סטטי ולא פתיחה ישירה של `index.html`:

```bash
npm install
npx serve .
```

ואז פותחים בדפדפן את `http://localhost:3000`.

## בדיקות

```bash
npm install
npx playwright install chromium firefox webkit
npm test                  # בדיקות לוגיקה (node --test)
npm run test:ui           # בדיקות ממשק: Chromium, Firefox, WebKit, במחשב ובסלולרי
npm run test:ui:chromium  # בדיקה מהירה ב-Chromium בלבד
npm run test:all          # הכל
```

בבדיקות הממשק התאריך מקובע ל-07.11.2026 ואזור הזמן ל-`Asia/Jerusalem`, כדי שהתוצאות יהיו יציבות.

**איפה הבדיקות רצות:**
- **בלי `BASE_URL`:** הבדיקות מריצות שרת מקומי (`tests/support/static-server.mjs`) שמגיש את האתר **רק** תחת `/lead-dashboard/`, כמו GitHub Pages. בשורש הוא מחזיר 404, ולכן נתיב מוחלט באתר או בבדיקה נכשל כבר מקומית.
- **עם `BASE_URL`:** הבדיקות רצות מול הכתובת שניתנה, ולא מופעל שרת מקומי. לדוגמה, אחרי הפרסום:

```bash
BASE_URL=https://taliasnir-prog.github.io/lead-dashboard/ npx playwright test --workers=1
```

- **בידוד:** כל בדיקה מקבלת סביבת דפדפן חדשה ומבודדת, עם localStorage ריק. הבדיקות כותבות רק נתוני דמה פיקטיביים, ולכן הן לא משפיעות על מבקרים אחרים באתר.
- **ניווט:** הבדיקות משתמשות ב-`page.goto('./')` ולא ב-`page.goto('/')`, שהיה מוביל לשורש הדומיין. בדיקה ב-`tests/logic/paths.test.js` מוודאת שלא חוזרים לזה, ושגם באתר עצמו אין נתיבים מוחלטים.
- **שרת ידני:** `npx serve .` (בהרצה המקומית למעלה) מגיש את האתר בשורש, והוא נועד לצפייה בלבד ולא לבדיקות.

**מגבלות הבדיקות:**
- WebKit של Playwright הוא המנוע של Safari, אבל הוא לא Safari אמיתי ולא iPhone.
- ב-Firefox "סלולרי" הוא חלון צר, כי ל-Firefox אין מצב סלולרי ב-Playwright.
- בדיקות הניגודיות והפוקוס מחושבות מצבעי ה-CSS. הן לא מחליפות סקירה ידנית או בדיקה עם קורא מסך.
- בדיקה בטלפון אמיתי עדיין לא בוצעה.

## שמירה מקומית: מה חשוב לדעת

- הנתונים נשמרים במפתח `leadDashboard.v1` ב-localStorage של הדפדפן.
- הם **לא מסתנכרנים** בין דפדפנים, מכשירים או משתמשים, ואין שרת.
- ניקוי נתוני האתר בדפדפן מוחק אותם, ובפעם הבאה ייטענו נתוני הדמה מחדש.
- הנתונים בהרצה מקומית ובאתר הציבורי נפרדים, כי לכל כתובת יש localStorage משלה.
- נתונים שמורים פגומים מוחלפים בנתוני הדמה, עם הודעה.
- אם הדפדפן חוסם שמירה, הדאשבורד עובד בזיכרון בלבד, מציג הודעה, והשינויים נעלמים ברענון.
- "איפוס לנתוני הדמה" מוחק את כל השינויים והלידים שנוספו, ומאפס את החיפוש והמסננים. התאריכים נוצרים לפי היום בזמן האיפוס, גם אם הדף נשאר פתוח אחרי חצות.
- **מגבלה של 500 לידים.** כשמגיעים אליה, "ליד חדש" מושבת ומוצגת הודעה. אפשר להמשיך לערוך לידים קיימים.
- לפני כל שמירה הנתונים נבדקים באותם כללים של הטעינה. ערך לא תקין לא נשמר ולא דורס את הערך התקין האחרון.
