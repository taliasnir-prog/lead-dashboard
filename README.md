## בדיקות

```bash
npm install
npx playwright install chromium firefox webkit
npm test                  # בדיקות לוגיקה (node --test)
npm run test:ui           # בדיקות ממשק: Chromium, Firefox, WebKit, במחשב ובסלולרי
npm run test:ui:chromium  # בדיקה מהירה ב-Chromium בלבד
npm run test:all          # הכל
```

בבדיקות הממשק התאריך מקובע ל-07.11.2026 ואזור הזמן ל-`Asia/Jerusalem`, כדי שהתוצאות יהיו יציבות.

**איפה הבדיקות רצות:**
- **בלי `BASE_URL`:** הבדיקות מריצות שרת מקומי (`tests/support/static-server.mjs`) שמגיש את האתר **רק** תחת `/lead-dashboard/`, כמו GitHub Pages. בשורש הוא מחזיר 404, ולכן נתיב מוחלט באתר או בבדיקה נכשל כבר מקומית.
- **עם `BASE_URL`:** הבדיקות רצות מול הכתובת שניתנה, ולא מופעל שרת מקומי. לדוגמה, אחרי הפרסום:

```bash
BASE_URL=https://taliasnir-prog.github.io/lead-dashboard/ npx playwright test --workers=1
```

- **בידוד:** כל בדיקה מקבלת סביבת דפדפן חדשה ומבודדת, עם localStorage ריק. הבדיקות כותבות רק נתוני דמה פיקטיביים, ולכן הן לא משפיעות על מבקרים אחרים באתר.
- **ניווט:** הבדיקות משתמשות ב-`page.goto('./')` ולא ב-`page.goto('/')`, שהיה מוביל לשורש הדומיין. בדיקה ב-`tests/logic/paths.test.js` מוודאת שלא חוזרים לזה, ושגם באתר עצמו אין נתיבים מוחלטים.
- **שרת ידני:** `npx serve .` (בהרצה המקומית למעלה) מגיש את האתר בשורש, והוא נועד לצפייה בלבד ולא לבדיקות.

**מגבלות הבדיקות:**
- WebKit של Playwright הוא המנוע של Safari, אבל הוא לא Safari אמיתי ולא iPhone.
- ב-Firefox "סלולרי" הוא חלון צר, כי ל-Firefox אין מצב סלולרי ב-Playwright.
- בדיקות הניגודיות והפוקוס מחושבות מצבעי ה-CSS. הן לא מחליפות סקירה ידנית או בדיקה עם קורא מסך.
- הבדיקות האוטומטיות רצות בדפדפנים במחשב, גם כשהן בודקות מסך קטן.
- בדיקה ידנית בטלפון אמיתי בוצעה ב-Samsung עם Chrome וב-iPhone (08.11.2026). הדפדפן ב-iPhone לא צוין, ולכן **אין בדיקה מתועדת ב-Safari**, ו-WebKit של Playwright לא מחליף אותה.

## שמירה מקומית: מה חשוב לדעת

- הנתונים נשמרים במפתח `leadDashboard.v1` ב-localStorage של הדפדפן.
- הם **לא מסתנכרנים** בין דפדפנים, מכשירים או משתמשים, ואין שרת.
- ניקוי נתוני האתר בדפדפן מוחק אותם, ובפעם הבאה ייטענו נתוני הדמה מחדש.
- הנתונים בהרצה מקומית ובאתר הציבורי נפרדים, כי לכל כתובת יש localStorage משלה.
- נתונים שמורים פגומים מוחלפים בנתוני הדמה, עם הודעה.
- אם הדפדפן חוסם שמירה, הדאשבורד עובד בזיכרון בלבד, מציג הודעה, והשינויים נעלמים ברענון.
- "איפוס לנתוני הדמה" מוחק את כל השינויים והלידים שנוספו, ומאפס את החיפוש והמסננים. התאריכים נוצרים לפי היום בזמן האיפוס, גם אם הדף נשאר פתוח אחרי חצות.
- **מגבלה של 500 לידים.** כשמגיעים אליה, "ליד חדש" מושבת ומוצגת הודעה. אפשר להמשיך לערוך לידים קיימים.
- לפני כל שמירה הנתונים נבדקים באותם כללים של הטעינה. ערך לא תקין לא נשמר ולא דורס את הערך התקין האחרון.

## חיבור שיעור 4: Airtable

קוד שיעור 4 הועלה לענף `feature/airtable-read-dashboard`. טיוטת השינויים: https://github.com/taliasnir-prog/lead-dashboard/pull/14. אין מיזוג ל-main. גרסת שיעור 4 פורסמה בנפרד: https://aido-lead-dashboard-lesson4.netlify.app/

מצב הקריאה החי מופעל באמצעות `npm start`, ואז `http://127.0.0.1:4318/lead-dashboard/?source=airtable`. Node 22 ומעלה נדרש. העתיקו `airtable.env.example` ל-`.env` ומלאו טוקן עם data.records:read וגישה לבסיס הפיקטיבי בלבד, מזהה בסיס ומזהה טבלה.

הטוקן נקרא רק בשרת. אין להעביר אותו בקוד האתר, בכתובת או ב-GitHub. הוספה, עריכה ואיפוס אינם זמינים במצב Airtable. עדכונים נעשים בבסיס ולחיצה על רענון טוענת אותם מחדש. ברירת המחדל ללא הפרמטר נשארת מצב הדמה המקומי. GitHub Pages אינו מריץ את שרת Node. האתר הציבורי של שיעור 3 נשאר כפי שהוגש. עבודת שיעור 4 נמצאת רק בענף `feature/airtable-read-dashboard`, ופורסמה בכתובת נפרדת. אין למזג ל-main או לשנות את האתר של שיעור 3 כל עוד הוא בבדיקה, אלא לפי הוראה מפורשת חדשה של בעל הפרויקט.

### בונוס API ציבורי

במצב Airtable מוצגים שלושה מועדים קרובים מלוח Hebcal לישראל. הבקשה ציבורית וללא טוקן, ואינה מעבירה פרטי לידים. התצוגה עצמאית: כשל במקור המועדים לא חוסם את הלידים. `js/holidays.js` מכיל את הבקשה ואת הסינון. מקור: https://www.hebcal.com/home/195/jewish-calendar-rest-api

### פרסום ב-Netlify

`netlify.toml`, `netlify/functions/leads.mjs` ו-`scripts/build-public.mjs` מוכנים לפרסום. הבנייה מעתיקה לתיקיית dist רק 7 קבצים ציבוריים. הטוקן מוגדר במשתני הסביבה של הפונקציה בלבד, יחד עם AIRTABLE_BASE_ID ו-AIRTABLE_TABLE_ID. הפרויקט הנפרד aido-lead-dashboard-lesson4 פורסם ב-11.11.2026 מהענף של שיעור 4. הטוקן נשמר כמשתנה סודי ב-Netlify. הכתובת הראשית מפנה למצב Airtable. נבדקו באתר החי טעינת 3 לידים, רענון, סינון Google, פרטי ליד לקריאה בלבד ו-3 מועדים מ-Hebcal. בקשת POST נדחית ב-405 וקבצים פרטיים מחזירים 404.
